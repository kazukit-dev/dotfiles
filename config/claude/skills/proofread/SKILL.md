# Proofread スキル

textlintが担うルールベースの静的解析（表記ゆれ・句読点・禁則文字）の**上位レイヤー**として機能する添削スキル。文脈・意図・読み手を踏まえ、AI編集者として文章の質を引き上げることを目的とする。

---

## 基本的な使い方

```
/proofread                          # 現在のファイルを添削
/proofread --genre=business         # ジャンルを明示して添削
/proofread --genre=blog path/to/file.md  # ファイルを指定して添削
```

---

## 実行手順

### 1. ファイルの読み込み

引数でファイルパスが指定された場合はそのファイルを読む。指定がない場合は現在作業中のファイル（直近で編集・表示されているファイル）を対象とする。

### 2. ジャンルの判定

`--genre` オプションが指定された場合はそれに従う。指定がない場合は文章の内容・構造・語調から以下のいずれかを自動判定する。

| ジャンル | キーワード・特徴 |
|---------|----------------|
| `academic` | 論文・レポート・研究・考察・序論・結論 |
| `business` | 報告書・メール・御社・弊社・拝啓・敬具・議事録 |
| `blog` | ブログ・SNS・ですます体でカジュアル・個人の意見 |
| `general` | 上記に当てはまらない場合のデフォルト |

### 3. 添削の実施

以下の優先順位で添削を行う。原文のスタイル・意図・声を尊重し、**必要最小限の修正**にとどめること。

**必ず確認する項目**
- 誤字・脱字・変換ミス
- 助詞の誤用（「は」「が」「を」「に」など）
- 句読点の位置・抜け
- 主語と述語のねじれ

**ジャンルに応じて確認する項目**
- 文章の流れ・段落のつながり
- 読みやすさ（一文が長すぎないか、情報密度は適切か）
- 論理構成（結論・根拠・例の順序）
- ジャンルに合わない語調・表現（ビジネスに砕けすぎた表現など）

**原則として変えないもの**
- 筆者のスタイルや個性
- 内容・事実・主張そのもの
- 箇条書きか文章かなどの構成スタイル（明らかに不適切でない限り）

### 4. 結果の出力

以下のフォーマットで出力する。

---

## 出力フォーマット

```
## 添削結果

**ジャンル判定**: [academic / business / blog / general]

---

### 差分

（変更のあった文を Git の unified diff 形式で示す。修正のない文はスキップ）

```diff
- 修正前の文
+ 修正後の文
```

各差分ブロックの直後に理由を1行で添える。

例:
```diff
- 本研究では機械学習を用いた手法を提案し、実験により有効性を確認した。
+ 本研究では機械学習を用いた手法を提案し、実験によってその有効性を確認した。
```
→ 「により」より「によって」のほうが書き言葉として自然。

---

### 添削済み全文

（修正を反映した完全な文章をそのまま出力）

---

### 総評

（3〜5文で文章全体へのコメント。良い点・改善点・全体の印象）
```

## ジャンル別の添削方針

### academic（論文・レポート）
- 論理の一貫性と根拠の明示を重視
- 受動態・客観的表現を適切に使っているか確認
- 「〜と思われる」「〜と考えられる」などの曖昧な表現を必要以上に使っていないか
- 接続詞（したがって・一方・また）が論理を正しくつないでいるか

### business（ビジネスメール・報告書）
- 敬語・ビジネス敬語の正確さ
- 冒頭の趣旨・本文・締めの構成
- 読み手が必要な情報を素早く取り出せるか
- 余計な前置きや過剰な謙遜表現

### blog（ブログ・SNS）
- 読み始めに興味を引けているか
- リズムと読みやすさ（長文の分割、改行）
- 語調の統一（ですます・だである）
- 読者への語りかけの自然さ

### general
- 上記のacademic・businessに準じた基本的な文章品質のチェック

---

## エラーハンドリング

| 状況 | 対応 |
|------|------|
| ファイルが見つからない | パスを確認してユーザーに報告 |
| 文章が極端に短い（1〜2文） | そのまま添削し「文章が短いため総評は省略します」と付記 |
| 修正箇所がない | 差分セクションに「修正箇所はありませんでした」と明記し、総評で良い点を伝える |
| コードブロックや表が含まれる | 自然言語部分のみを対象とし、コード・表は添削しない |

## 使用例

```
# ブログ記事を添削
/proofread --genre=blog draft.md

# ジャンル自動判定で添削
/proofread report.md

# 現在開いているファイルを添削
/proofread
```
